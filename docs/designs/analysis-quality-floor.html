01 / What fails

One model call writes the facts and the numbers.

Reviewers saw these seven failures across four rounds. Open a tab to see one real example.

ProofBlind review, all rounds

A quote can say the opposite of the claim.

“A finding cites the persona who said the opposite.”
Investor reviewer, round 1

Problem

The quote is real. It does not support the claim. The check tests only that the words exist.

Cause

One call writes the claim and picks the quote. No step reads them together.

Fix

Add a check. Read the claim and its quotes. If the quote does not support the claim, fix the claim or drop it.

CountsBlind review, all rounds

A count can be higher than the quotes.

“Every finding cites three personas and claims five.”
Investor and growth reviewers

Problem

A claim says five of five. It shows three quotes. A split leaves out one person.

Cause

The model writes the count. A missing quote lowers the count. The text can still say “all”.

Fix

Count people from claims. A split must add up to the full group. If it does not, drop the split.

ProofBlind review, all rounds

The report can invent a fact.

“A false forward-date complaint and a wrong growth calculation become documented reasons to say no.”
Investor reviewer

Problem

The report copies a persona's math. It does not check the source. A wrong number becomes a real reason to say no.

Cause

The report sees the personas' answers, not the input. It cannot tell a bad claim from a bad persona answer.

Fix

Give the report a short fact sheet. List the offer, prices, claims, and call to action. Check each fact against it.

VoicesBlind review, all rounds

Every persona sounds the same.

“Independent corroboration is actually one script in eight costumes.”
Founder reviewer

Problem

They open the same way. They read in the same order. They make the same point. The group looks big, but the proof is thin.

Cause

Every persona gets the same reading task. Only the voice changes.

Fix

Give each persona a different job. One buys. One uses. One blocks. One supports. Ask each for a verdict.

RoleBlind review, all rounds

A persona can change role.

“Roles, pronouns, and backstories change.”
Marketer and growth reviewers

Problem

A persona is a buyer. The summary makes them a vendor. The question is never tested.

Cause

The report copies the input's idea of the reader. Nothing checks the persona's role.

Fix

Store each persona's role and stake. Check the summary against them.

ShapeBlind review, all rounds

One shape does not fit every input.

“There is no place to record a drop-off timestamp.”
Growth reviewer

Problem

A video script gets the same stages as a pricing page. A stop time has no field. So no one stops.

Cause

The stages assume a buyer and a page. The report does not know the input type.

Fix

Add an input type and a place for a section or time. Keep the five stages.

RegressionBlind review, round 3

A quick fix can make the score worse.

“A reaction supported 8 of 8 was reported as 3 of 8.”
Blind review, round 3

Problem

A patch replaced “all” with the quote count. The model gave three quotes for a point all eight people made. The score fell from 6 to 5.

Cause

It counted quotes, not claims. Three quotes do not mean three people.

Fix

Count all claims first. Add quotes after. A missing quote must not lower the count.

    04 / Plan

    Four steps. Start with the risk.

    Do S1 first. Each step has a test that can say no. Wait for real output before you plan S3 and S4.

    S1 Build counts and check quotes Hardest +

    Build the claim list. Group claims. Count people in code. Check quotes. Write the answer.

    Test: unit tests and a real five-person report. No change to: models, input, personas, or UI.

    • Pass T1 to T5.
    • If grouping fails, use the per-persona answers and a simple summary.
    • If a quote fails, drop the claim. Never pad a count.
    S2 Make personas differ Design risk +

    Give each persona a job, a stake, a current tool, and a task. Add a verdict.

    Test: blind score for different voices on one input. No change to: the answer.

    • Jobs: buyer, user, blocker, supporter.
    • Verdict: adopt, trial, reject, undecided.
    • Check name, pronoun, and role.
    S3 Add facts and input types Data risk +

    Pull the exact prices, claims, and call to action. Add a section or time to each stage.

    Test: a video shows a real stop time. No fake numbers. Keep five stages.

    S4 Score the output Score risk +

    Use five reviewer roles on ten reports. Record the median and every failure. The test must be able to fail.

    Test: median 8/10 and no repeated failure. No change to: prompts.
